# 구글 시트(LAD) 연결 안내 — 선생님이 직접 하는 마지막 단계

게임 쪽 준비는 모두 끝나 있습니다. 아래 순서대로 **구글 시트 하나를 만들고, 코드 두 개를 붙여 넣고, 주소와 비밀 문자열을 Railway에 넣으면** 연결이 끝납니다. 15분쯤 걸립니다.

- 연결하기 전에 한 수업 기록도 사라지지 않습니다. 학급 서버가 기록을 모아 두었다가, 연결하면 한꺼번에 시트로 보냅니다.
- 시트에는 **학생 이름이 가지 않습니다.** 반 코드 · 번호 · 플레이어키(이름에서 만든, 되돌릴 수 없는 열쇠)만 갑니다. 출석부로 번호와 학생을 연결하세요. 익명이 아니라 '가명' 기록입니다.

---

## 1. 새 스프레드시트 만들기

1. 구글 드라이브 → **새로 만들기 → Google 스프레드시트**
2. 이름을 `전기마스터타운_LAD`로 바꿉니다.
3. 기존 '소크라테스 AI 튜터' 시트와는 **다른 파일**이어야 합니다. 그 시트는 건드리지 않습니다.

## 2. 코드 두 개 붙여 넣기

1. 새 시트에서 **확장 프로그램 → Apps Script**를 엽니다.
2. 왼쪽 `Code.gs`의 내용을 모두 지우고, 이 폴더의 `GameBridge.gs` 내용을 통째로 붙여 넣습니다.
3. 왼쪽 **파일 ＋ → 스크립트**를 눌러 이름을 `Analysis`로 짓고, `Analysis.gs` 내용을 붙여 넣습니다.
4. 💾 저장(Ctrl+S)합니다.

> ✅ 정상: 왼쪽에 `GameBridge.gs`(또는 `Code.gs`)와 `Analysis.gs` 두 파일이 보입니다.

## 3. 비밀 문자열 만들기 (메뉴 한 번)

1. 스프레드시트 탭으로 돌아가 **새로고침**합니다. 위쪽 메뉴에 **🎮 게임 LAD**가 생깁니다. (안 보이면 10초 뒤 한 번 더 새로고침)
2. **🎮 게임 LAD → 🔑 비밀 문자열 만들기 (처음 한 번)**를 누릅니다.
3. 처음에는 "승인 필요" 창이 뜹니다. **계속 → 내 구글 계정 선택 → 고급 → (안전하지 않은 페이지로) 이동 → 허용**을 누르고, 메뉴를 한 번 더 누릅니다.
4. 창에 나온 긴 글자를 **메모장에 잠시 복사**해 둡니다. 5단계에서 Railway에 넣습니다.

> 이 값은 스크립트 속성 `GAME_SHARED_SECRET`에 자동으로 저장됩니다. 채팅·문서·시트 칸에는 붙여 넣지 마세요.

**(선택) 스크립트 속성 더 넣기** — Apps Script 왼쪽 ⚙️ **프로젝트 설정 → 스크립트 속성 → 속성 추가**

| 속성 | 값 | 없으면 |
|---|---|---|
| `TEACHER_ALERT_EMAIL` | 위험 신호(자해·괴롭힘 등) 알림을 받을 학교 메일 | 메일 알림 없이 시트에만 '위험' 표시 |
| `GEMINI_API_KEYS` | **결제 계정(Cloud Billing)이 연결된** 프로젝트의 Gemini 키 (여러 개면 쉼표) | AI 요약·편지 초안 없이 규칙 통계만 |

> Gemini는 **수업 후 선생님이 메뉴로 실행할 때만** 쓰입니다. 학생이 게임하는 동안에는 어떤 AI도 부르지 않습니다. 무료 키는 입력 내용이 구글 제품 개선에 쓰일 수 있으니 결제 계정 키를 쓰세요.

## 4. 웹 앱으로 배포하기

1. Apps Script 오른쪽 위 **배포 → 새 배포**
2. ⚙️(유형 선택) → **웹 앱**
3. 설정
   - 설명: `게임 연결`
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. **배포** → 권한 승인 창이 뜨면 3단계처럼 허용합니다.
5. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/……/exec`)을 복사합니다.

> "모든 사용자"여도 괜찮은 까닭: 게임 서버만 이 주소를 알고, 비밀 문자열이 틀린 요청은 모두 거절합니다. 이 주소는 학생에게 알려 주지 않습니다.

## 5. Railway에 두 값 넣기

1. [Railway](https://railway.app) → 전기 마스터 타운 프로젝트 → **web** 서비스 → **Variables**
2. **New Variable**로 아래를 넣습니다.

| 이름 | 값 | 필수 |
|---|---|---|
| `GAS_WEBAPP_URL` | 4단계의 웹 앱 URL (`/exec`로 끝남) | 필수 |
| `GAS_SHARED_SECRET` | 3단계의 비밀 문자열 (한 글자도 다르면 안 됨) | 필수 |
| `CLASS_CODES` | 쓸 반 코드를 쉼표로 (예: `6301,6302`). 넣으면 다른 코드는 거절하고, 하나만 넣으면 학생 화면에 미리 채워짐 | 선택 |

3. 화면 위쪽에 **Deploy**(또는 Apply changes) 버튼이 뜨면 누릅니다. 서버가 새 값으로 다시 켜집니다. 1~2분 기다립니다.

## 6. 연결 확인

- **시트를 새로고침했을 때 `차시설정` 탭이 생기고 L1 · L2 · L3 세 줄이 보이면 연결 성공**입니다. 서버가 켜질 때 대본 정보를 보내기 때문입니다.
- 🎮 게임 LAD → **① 연결 점검**에서 ✅ 표시를 확인합니다.
- Railway → web → **Deployments → View Logs**에 `[lad] 구글 시트 연결: 차시 설정 동기화됨`이 보이면 서버 쪽도 정상입니다.
- 학생 한 명(선생님 시험 계정)으로 정리 회의를 해 보면 10초 안에 `게임로그` 탭에 줄이 생깁니다.

## 7. 수업 흐름 (학생 화면 → 시트)

1. 학생이 차시 구역에 처음 들어오면 **반 코드와 번호**를 한 번 적습니다. (이름은 적지 않습니다)
2. 그 차시 퀘스트를 모두 마치면 구역 끝 **「○차시 정리 교실」**에서 인물들이 큰 칠판 앞에 모여 **S-E-R 정리 회의**를 엽니다.
   - 판정은 학급 서버의 규칙 엔진이 합니다. 정답 낱말은 서버에만 있습니다.
   - 학생 답 한 번 = `게임로그` 한 줄. 칠판에는 오늘의 한 문장 · 잘한 점 · 다음에 생각해 볼 질문이 자동으로 정리됩니다.
3. 정리 회의를 마쳐야 그 차시가 ✅ 완료되고, 세 차시를 모두 마치면 광장 점등식이 열립니다.
4. 점등식 뒤 **시청 기록실**에서 시장님과 볼트 박사가 세 차시 문장과 선생님 편지를 모아 **배움 기록 문서**(내려받기 · 한글/워드용 · 인쇄/PDF · 글 복사)를 만들어 주고 게임이 끝납니다.

## 8. 수업 후 선생님이 할 일 (시트 메뉴)

1. **② 차시 분석 실행** → 차시 ID 입력: `L1`, `L2`, `L3`
   - `차시요약` 탭에 학생별 규칙 통계 + (키가 있으면) AI 요약 · 편지 초안이 채워집니다.
   - 위험 신호가 있는 학생은 AI 분석을 하지 않고 "교사직접확인"으로 표시됩니다.
   - 6분 안에 못 끝나면 1분 뒤 자동으로 이어서 합니다.
2. `차시요약`에서 **AI피드백초안**을 읽고, 고칠 곳은 **교사수정피드백** 칸에 고쳐 쓴 뒤 **승인**에 체크합니다. (승인한 것만 학생에게 갑니다)
3. 다음 차시에 학생이 구역에 들어오면 **📮 마을 우체부**가 편지를 전해 주고, 학생 답장이 **학생반응** 칸에 기록됩니다. (승인 뒤 최대 3분 안에 반영)
4. **④ 차시 성찰표 만들기** → `차시성찰_L1` 탭에 AIEDAP '여섯 관점' 점검표가 데이터로 채워집니다. 다시 만들어도 선생님이 쓴 칸은 지워지지 않습니다.

## 9. 탭 구조

| 탭 | 누가 쓰나 | 내용 |
|---|---|---|
| 게임로그 | 게임 서버 (추가만) | 정리 회의 답 · 차시 첫 진입 · 활동 완료 · 편지 답장, 한 줄 = 한 기록 |
| 차시요약 | 분석 메뉴 + 선생님 | 학생 × 차시 한 줄. 선생님 칸(교사수정피드백·승인·전달시각·학생반응)은 분석이 덮어쓰지 않음 |
| 차시설정 | 게임 서버 | 대본(lessons/L*.json)의 성취기준 · 목표 개념 · S/E/R 기준 |
| 차시성찰_L1 … | 성찰 메뉴 + 선생님 | 여섯 관점 점검표 + 4칸 성찰 |
| 오류기록 | 자동 | 내부 오류 (API 키는 가려서 기록) |

## 10. 잘 안 될 때

| 보이는 것 | 고칠 곳 |
|---|---|
| `차시설정` 탭이 안 생김 | Railway 변수 이름 철자(`GAS_WEBAPP_URL`, `GAS_SHARED_SECRET`), URL이 `/exec`로 끝나는지, 서버가 다시 켜졌는지 |
| 로그에 `unauthorized` | 스크립트 속성 `GAME_SHARED_SECRET`과 Railway `GAS_SHARED_SECRET`이 한 글자라도 다름 → 🔑 메뉴로 값을 다시 보고 Railway에 다시 붙여 넣기 |
| 로그에 `non_json_…` | 배포의 "액세스 권한"이 **모든 사용자**인지. 코드를 고쳤다면 **배포 관리 → ✏️ → 버전: 새 버전 → 배포** |
| 편지가 학생에게 안 감 | `승인` 체크, 편지 칸(교사수정피드백 또는 AI피드백초안)이 비어 있지 않은지, 학생이 반 코드를 바르게 적었는지 |
| 정리 회의를 잠시 끄고 싶음 | Railway 변수 `NPC_REFLECTION_ENABLED` = `false` (정리 교실은 남지만 회의 없이 차시가 완료됨) |
| 편지만 끄고 싶음 | `FEEDBACK_LETTER_ENABLED` = `false` |
| 편지의 'AI 도움 + 선생님 확인' 표시를 끄고 싶음 | `SHOW_AI_LABEL` = `false` |

개발자용 확인 명령(서버와 같은 환경 변수로): `npm run gas:ping` · `npm run gas:smoke`(반코드 TEST로 시험 기록 3건)

## 11. 알아 둘 한계

- 키워드 판정이라 오탐 · 미탐이 있습니다. 그래서 AI 분석과 선생님 판단을 두 번째 · 세 번째 평가자로 두고, `차시요약`의 '단계일치'로 차이를 봅니다.
- 위험 신호 감지는 보조 수단입니다. 선생님의 관찰을 대신하지 않습니다.
- 서버가 다시 켜지는 순간 진행 중이던 정리 회의는 처음부터 다시 엽니다. 이미 보낸 기록은 남습니다.
